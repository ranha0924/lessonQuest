## Behavior and containment evidence

- Queue scope is strict `(lqs_<64 lowercase hex>, organization UUID)`. The web adapter has no unscoped application list/clear, and list, put, remove, clear and expiry prune all use the exact scope. Adapter metadata and embedded event organization must both match; corrupted current-scope records are deleted before delivery, while unrelated valid scopes remain untouched. Browser storage inspection found one strict event plus timestamps/counters and no authorization, bearer value, correctness, title or hint.
- Exact event ID/body staging precedes start/answer/retry/completion delivery. Success and server duplicate remove the local record; network/retryable outcomes retain it with 2/4/8/16/32/60-second bounded backoff; terminal API authority/lifecycle outcomes remove it and show safe re-entry guidance.
- A scope contains at most 20 events and records expire after 24 hours. One pending event per attempt blocks competing writes in the coordinator/player. Queue subscriber errors cannot alter durable delivery.
- Concurrent enqueue staging is serialized in invocation order. Only the FIFO head can reserve delivery, so `sending`, `lastAttemptAt` and backoff belong to one event at a time. Every pre-delivery await is tied to the invocation's lifecycle generation.
- Session-ended and preview data reset invalidate in-flight results before clearing and disposing only the active account/organization. Late success/terminal/retryable outcomes cannot emit or recreate a cleared record. Ordinary component unmount disposes listeners and retains the original staged record even if an in-flight retry settles later. If IndexedDB is unavailable, hosts keep the existing in-memory retry path; there is no localStorage fallback or durable credential.
- Service-worker registration occurs only for an explicit development preview or configured real session. Both hosts warm already-loaded hashed assets after the worker is active. The worker reads and writes only the current LessonQuest named cache, caches successful same-origin shell/static GET responses, and rejects authorization, `/health`, `/organizations/`, `/api/`, cross-origin, opaque, error and non-OK responses. It deletes only old `lessonquest-shell-*` caches.

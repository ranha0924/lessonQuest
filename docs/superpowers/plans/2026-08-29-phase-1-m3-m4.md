# Phase 1 M3–M4 Implementation Plan

> **Execution:** Follow this plan sequentially with test-driven development. Run focused RED/GREEN tests per task, one full implementer check after all tasks, then exactly one fresh independent final review.

**Goal:** Deliver M3 Science Studio and M4 assignment/student play as one secure local vertical slice from generated science JSON through teacher progress.

**Architecture:** Strict shared contracts feed a pure Science Studio parser/validator/compiler. A tenant-safe PostgreSQL-compatible repository owns immutable version, assignment, attempt, append-only event, and projection state. The Hono API exposes role-scoped workflows. A fixed React renderer and SDK provide teacher preview and student play without executing generated code.

**Tech stack:** TypeScript 6.0.3, Zod 4.5.2, Hono 4.13.5, PGlite 0.5.8, Vitest 4.1.11, React/React DOM 19.2.8, Vite 8.2.2, `@vitejs/plugin-react` 6.1.1, React Testing Library 16.3.3, jsdom 30.0.1, pnpm 11.24.0.

**Design:** `docs/superpowers/specs/2026-08-29-phase-1-m3-m4-design.md`

## Global constraints

- Do not access Firebase, production services, private student data, or existing repository deployments.
- Do not push, merge, or deploy.
- Do not accept free HTML/JS/CSS/URL fields in generated specifications.
- Every resource lookup and mutation rechecks active database-backed roles and tenant/class ownership.
- Validation and teacher approval are separate persisted decisions. Neither can be inferred from client input.
- Approved content is immutable and runner/player session issuance recomputes its canonical hash.
- Use exact synthetic UUIDs and deterministic timestamps in tests.
- Record original LessonQuest implementation in `docs/SOURCE_PROVENANCE.md`; do not claim unavailable Science LAB code was copied.
- Do not run the whole suite between tasks. Run only focused RED/GREEN commands until final verification.

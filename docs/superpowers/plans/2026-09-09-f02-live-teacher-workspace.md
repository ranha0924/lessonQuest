## Product and deployment boundary

The live teacher entry shows Google login, server registration/connection status, approved lesson-space selection and the existing F01 LessonInputWorkspace. It saves/reloads/edits real server lessons and keeps AI generation visibly disabled. It never seeds synthetic users/classes/lessons, accepts a window-injected session or grants first-visitor teacher rights. The legacy demo/development preview and its science/classroom/player flows remain available in their existing explicit local build modes and tests. This first live surface does not expose unprepared student/admin/publishing endpoints through the production gateway; expansion requires corresponding server-role grants and gates. No model provider, checkout or administrator AI bypass is added.

## Server implementation

1. Add a strict shared teacher-session contract (userId UUID, up to100 approved organization {id,name} records, literal AI_BILLING_NOT_CONFIGURED state) and a SQL TeacherSessionRepository. Read only the current authenticated internal user, active TEACHER role and active teacher/ORG_ADMIN memberships/organizations; never trust browser organization/role claims. Return an empty organization list for a still-active teacher lacking approved spaces, and a safe existing authority error for a revoked/disabled/nonteacher user. No identity provisioning or profile/email output occurs in this endpoint.
2. Add optional session repository registration to createApp at GET /session, using its existing Firebase AuthProvider and safe error/trace boundary; no-store on every session response. Existing F01 middleware/AI denial remains unchanged.
3. Add a Node-only server-runtime module (not root/browser barrel). Strictly parse explicit environment configuration: dedicated project lessonquest-df4b0, trusted HTTPS origin, separate restricted LESSONQUEST_DATABASE_URL and a server-only Firebase service-account JSON credential. Parse only projectId/clientEmail/privateKey into firebase-admin cert; reject mismatched project, emulator config, malformed/oversized values and unsafe database config without printing raw data. Reuse FirebaseAuthProvider with revocation verification and PostgresDatabase with schema lessonquest, bounded pool/verified TLS/timeouts. Add firebase-admin14.3.0 as an API workspace dependency if cert conversion belongs in that module; do not duplicate OAuth/JWT signing logic.
4. Initialize one cached runtime per function instance with single-flight setup, bounded failure/retry behavior and resource cleanup. Startup performs read-only schema/version and actual runtime-role readiness checks through a narrow read-only API; it must never import/call migrateLessonQuest/bootstrapTeacher/initializeSchema as a startup action. No LocalAuth/PGlite/demo fallback, OpenAI environment read, DDL, owner URL fallback or identity write. Missing configuration/readiness failure returns safe503/no-store with traceId and no raw SDK/SQL errors.
5. Add a Vercel Fetch function entry in root api/index.ts, using the existing Vite site. Accept only /api/session, /api/health and exact F01 collection/item/generation paths with their supported methods. Strip the /api prefix through a streaming Request clone before passing to createApp so existing route parsing/body limits remain correct; preserve method/body/origin/authorization, ignore untrusted forwarding headers, and set no-store on all gateway responses. All other /api paths get safe404 JSON. AI route remains unconditional deny. Health performs no schema mutation and does not return secrets/role details.
6. Add explicit /api routing before the SPA fallback in vercel.json, use live Firebase browser mode with both demo/preview flags false, and keep existing Vite output location. Restrict CSP to self plus the dedicated Firebase auth frame and required official Google/Firebase auth endpoints; no broad wildcard/script eval exceptions. Configure no-store API responses and account for popup opener behavior. Verify Vercel's actual route/export contract with official documentation and a local request harness, then on the eventual deployed exact commit; no duplicate deployment.

## Browser implementation

1. Pin official Firebase JavaScript SDK12.18.0 (registry version checked2026-09-09) in the catalog/web package and lockfile. Import only Firebase app/auth browser modules; no Admin SDK/server module. Validate public VITE_FIREBASE_PROJECT_ID/authDomain/appId/apiKey against the dedicated project, and show a safe setup state if missing. Firebase web apiKey is public configuration; server credential/OpenAI key must never have VITE_ prefixes. Add a build guard rejecting public environment variables named for server secrets without printing values.
2. Implement a small injected browser-auth interface and real Google popup adapter with Firebase SDK session persistence. SDK manages its token store; do not copy credentials to window/new localStorage fields or logs. Subscribe to identity changes, support sign-out, and keep SDK errors behind safe Korean messages. Popup/provider login failures, setup failures, registration/authorization failures and no approved lesson space have actionable distinct UI states where server evidence allows; do not falsely label an unverifiable account as approved.
3. Extend HTTP client authorization to allow an asynchronous token provider and a narrow /api path prefix while preserving existing client defaults. Add a session assertion before dispatch and after response JSON parsing. Live transport stays same-origin, credentials omit/cache no-store/redirect error, gets a current Firebase ID token and refuses when the bound identity/session has changed. Abort outstanding requests and invalidate epochs immediately on logout/user switch. Delayed token, session response, saved-list/read/mutation result cannot enter another user's state. Never cache lesson content/tokens in the service worker or enable the student offline queue for this surface.
4. Add LiveTeacherWorkspace in the existing cosmic visual style with Google login, connecting/loading/registration status, sign-out, an approved-space selector, and a keyed LessonInputWorkspace. On account/space change unmount and clear old editor/data before rendering new content. Unknown teachers receive no lesson API capability; their own Firebase UID may be shown explicitly as a noncredential registration identifier for the operator, never a token or automatic linking action. Retry confirms current session before loading. AI stays disabled independently of any client state/flags.
5. main.tsx selects this entry only in explicit VITE_LIVE_MODE, before legacy injected-session handling, and rejects simultaneous live/demo/preview modes. Existing explicit synthetic modes and their test expectations remain unchanged. The service worker's /api/authorization cache exclusions remain enforced and live session/content responses get no-store.

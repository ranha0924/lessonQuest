# F02 Firebase dependency loading on Vercel

The fba0dc3 Preview builds successfully but every function invocation exits before its handler: jwks-rsa4.1.0 synchronously requires ESM-only jose6.2.12 while Vercel disables Node's synchronous require(esm). Actual logs are preserved in `.verification/f02-vercel-runtime-preview.log`; the same import fails locally under `node --no-experimental-require-module` in `.verification/f02-vercel-esm-import-red.log`. The registry's latest jwks-rsa is still4.1.0. [Upstream issue507](https://github.com/auth0/node-jwks-rsa/issues/507) and [open PR508](https://github.com/auth0/node-jwks-rsa/pull/508) document the same defect; an open PR is not an accepted release.

1. Before patching, add a child-process regression under Node's actual no-experimental-require-module flag. Use a minimal nonsecret environment, no external network/credentials. Import the actual built server runtime and require the actual Firebase dependency graph; assert unconfigured session503, unknown/query route404, no-store and no crash. Separately run a loopback JWKS server with generated RSA/EC public keys, request keys through the real jwks-rsa client and verify signatures with Node crypto. Cover unknown kid, malformed/private/encryption-use JWK filtering and the exposed passport callback integration with valid/malformed/unsupported-alg tokens. Those fixtures are never Firebase identities or release assets.
2. Use pnpm11.24's supported patch/patch-commit workflow for exactly jwks-rsa4.1.0. Remove top-level require('jose') in src/utils.js and src/integrations/passport.js. In the already-async retrieveSigningKeys, await import('jose') before existing key processing. Make passport's callback-provider implementation async and import jose within its existing decode try/catch; keep the existing callback/error/algorithm/key-selection logic. Preserve all jose/Firebase/package versions, key/algorithm/issuer/audience/revocation behavior and the AI deny route. Do not downgrade crypto dependencies or enable runtime flags that the host intentionally disabled. Record the minimal patch in patches/, pnpm-workspace.yaml and pnpm-lock.yaml, with provenance and MIT license reference.
3. Run intended RED/GREEN, frozen install, focused Firebase/API/server/denial and browser-boundary regressions, root/API types, lint/format, full check and production/all-dependency audits. Run actual Node-flag process probes after a frozen install so the patch is proved reproducible. Inspect lock delta to reject unrelated package changes. Build/scan live artifacts for server/secret/fixture leakage; unchanged full PostgreSQL/browser evidence remains inherited, while the full required CI repeats all hosted checks on the new head.
4. Freeze patch/config/lock/test manifest and obtain fresh independent nonimplementer review86+ before push. Reviewer exercises real key retrieval/negative cases and inspects callback behavior as well as safe server import. Corrected-head CI, successful hosted API503/404 instead of process500 and matching deployment SHA are required before remote provisioning/main release. Keep prior production and AI denial. Remove the patch only after a separately verified upstream release provides the same compatibility.

Scope is a narrowly pinned dependency compatibility patch plus tests/provenance. No application authorization, token-verification implementation, student data, credentials, schema, reference repository or new paid resource changes. A callback provider is consumed through its existing callback; the regression verifies callback completion once and a safe malformed-token result despite its internal async implementation.

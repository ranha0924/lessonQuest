## Interfaces and files

- Add `packages/auth/src/firebase.ts`, exposed only through the `node` condition of `@lessonquest/auth/firebase`; never export from the browser-used root barrel. Pin official `firebase-admin` **14.3.0** (npm engines Node >=22; workspace Node >=24). Production factory uses `initializeApp({ projectId, credential }, uniqueName)` and `getAuth(app).verifyIdToken(token, true)`; provide an explicit async `close()` to delete the owned app. No ambient default app, automatic credential search, emulator or local-auth fallback.
- `FirebaseAuthProvider` implements AuthProvider with injected `{projectId, verifier, identities, timeoutMs?}`. Verifier has SDK-compatible `verifyIdToken(token, true): Promise<unknown>`; identities has `findActor(projectId, uid): Promise<Actor | null>`. Injection allows deterministic no-network boundary tests; factory composes the real SDK. The required `Credential` must be passed explicitly by the future server bootstrap.
- Strict Bearer compact-JWT syntax and 16 KiB maximum header precede SDK calls. Require verified Google provider, verified email, configured audience/issuer, uid matching sub, bounded uid, valid exp/iat/auth_time, and no Firebase tenant claim. Ignore all custom roles, memberships and emails for account linking. Token validation stays the SDK's responsibility; local tests do not claim to prove Google's cryptography.
- Map all provider/lookup failures to a fresh safe AuthenticationError without cause or upstream text. Whole resolution has a 10-second default deadline (configurable 1–30 seconds). A timed-out verifier must never proceed to identity lookup later. At most 16 underlying resolutions per provider may remain active, including expired operations until they settle, to bound work. This is a process resource bound, not a distributed rate limiter.
- Reject `FIREBASE_AUTH_EMULATOR_HOST` whenever configured, including if it changes after construction. Validate project IDs, timeout, identity shape; cloned actors prevent caller mutation. No caching of roles or identities.
- Add `packages/db/src/firebase-identity-repository.ts` with only `findActor`. A single SQL snapshot joins `firebase_identities`, active users, and active compatible organization memberships in active organizations. Student membership requires current STUDENT; teacher/admin membership requires current TEACHER or SUPER_ADMIN. No match/disabled/invalid/over-100-membership actor returns null. Existing per-operation authorization remains authoritative after this read.
- Extend local `schema.ts` with `firebase_identities(project_id, uid, user_id, status)` after users: primary key `(project_id, uid)`, unique `(project_id, user_id)`, user FK, ACTIVE/DISABLED status, bounded project/uid CHECKs. This is an additive local schema declaration. A later checksummed PostgreSQL migration must carry it into the dedicated DB. No automatic linking by email and no public identity write route.
- Add dedicated auth, DB, and real HTTP/PGlite tests. Export repository through DB root; it has no SDK dependency. Update lockfile, evidence and setup documentation. Original LessonQuest code only.

Provider closes only its uniquely named SDK app. No token/uid/email/credential is logged or put in URLs. Firebase outbound requests are confined to the real SDK; tests use synthetic values and do not acquire service credentials.

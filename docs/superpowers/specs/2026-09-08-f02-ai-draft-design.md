작성일: 2026-09-08. 상태: 실제 로그인·서버 저장 범위 확정. 전용 인프라 연결 및 구현 게이트 준비 중.

## 요구와 확인된 기준

- 사용자 요청: F02 진행, 실제 AI 생성 연결까지 구현.
- 후속 확정: OpenAI API 사용. 실제 교사 로그인과 서버 영구 저장까지 포함. 최초 확인 당시에는 Firebase·PostgreSQL 전용 프로젝트가 없었고, 아래 연결 진행 갱신에서 생성 완료 보고를 기록했다. 기본 모델 후보는 GPT-5.6 Luna이며 실제 계정 사용 가능 여부를 연결 후 확인한다.
- 연결 진행 갱신: 사용자가 Firebase 프로젝트 `lessonquest-df4b0` 생성과 Neon/Vercel 연결 완료를 보고했다. Vercel은 기존 유료 계정을 사용한다. 2026-09-09 Vercel 로그인 후 Firebase Google 제공자·웹 앱과 Neon `neon-aero-jacket` 연결을 직접 확인했다. 승인 도메인·서버 비밀·Neon 이메일 활성화·환경 분리에는 후속 설정이 필요하다. 상세 상태는 `docs/F02_CONNECTION_SETUP.md`에 기록한다. 키나 DB 연결 문자열은 취득하지 않았다.
- 기획서 F02: 수업 내용·목표에 기반한 단일 형식 초안, 설명·문항·정답 기준·힌트, 진행 상태·실패·재시도, 필수 항목 오류 표시, 교사 검토.
- `docs/PROJECT_CANON.md` 및 `docs/INTEGRATION_PLAN_V2.md`를 준수한다. 생성과 독립 검증을 분리하고 교사 승인 전 게시하지 않는다.
- F01 의존 기준은 `codex/f01-lesson-inputs`의 `fe20d4b`이다. 독립 심사 Attempt 2는 98/100 PASS이며, 현재 확인한 `origin/main`에는 아직 통합되지 않았다. F02 통합 전에 F01의 CI·통합 상태를 다시 확인한다.
- 현재 배포는 Vite 정적 미리보기이며 Hono, 합성 인증, PGlite가 브라우저에서 실행된다. 이 인증은 외부 유료 AI 호출 권한으로 신뢰할 수 없다.

## 선택한 운영 구조

1. Firebase Authentication의 Google 로그인을 사용한다. LessonQuest 전용 새 프로젝트만 연결한다. Firebase는 인증에 사용하고 Firestore로 현재 SQL 저장소를 전면 교체하지 않는다.
2. Neon PostgreSQL을 기존 LessonQuest Vercel 프로젝트에 연결하는 구성을 제안한다. 다른 서비스 DB는 사용하지 않는다. 개발·preview와 production DB를 분리한다. 유료 요금제 가입이나 업그레이드는 별도 사용자 승인이 필요하다.
3. 기존 Vercel에 서버 API를 추가한다. Node 런타임에서 Firebase 토큰 확인, PostgreSQL 권한 확인 및 OpenAI 호출을 수행한다. Cloudflare는 이 단계의 필수 의존성이 아니다.
4. API 키 값은 문서·채팅·브라우저에 넣지 않고 서버 비밀 환경변수로만 설정한다. Firebase 웹 설정은 공개 설정과 서버 자격증명을 구분한다.
5. 기존 렌더러는 FORCE_MOTION 실험을 포함한 과학 형식이다. 초기에는 힘과 운동 단원으로 명시적으로 제한하는 방안을 권장한다. 다른 단원을 이 실험에 억지로 끼워 맞추지 않는다. 일반 단원 지원은 별도 체험 형식·검증·렌더러 설계가 필요하다.

### 로그인과 최초 교사 등록

Google 로그인 자체가 교사 자격이나 기존 기관 접근권한을 부여하지 않는다. Firebase Admin으로 서명·프로젝트·만료·철회/비활성 상태를 확인하고 검증된 uid를 서버의 고유 identity 행에 연결한다. 웹에서 보낸 역할·조직·이메일만으로 기존 계정에 연결하지 않는다.

초기 공개 가입자는 인증만 완료한 상태로 두고 기존 기관 및 AI 호출은 거부한다. 첫 운영자는 전용 설정 절차에서 명시적으로 지정한 Firebase uid로만 부트스트랩한다. 이후 교사 등록은 운영자가 승인한 초대/등록 기록에 연결한다. 첫 로그인 사용자나 특정 이메일 도메인을 자동 관리자로 만들지 않는다. 사용자 입력으로 SUPER_ADMIN을 만들 수 없어야 한다.

로그인 실패, 미등록/승인 대기, 기관 비활성, 세션 만료를 별도 화면 상태로 표시한다. 새로고침과 다른 브라우저 로그인 후에도 서버에서 저장한 원문과 생성 이력을 다시 읽는다. 로그아웃/사용자 전환 시 메모리와 사용자별 오프라인 데이터를 정리하며 다른 교사 자료가 잠깐 나타나는 것도 차단한다.

### PostgreSQL 전환

현재 저장소 생성자가 직접 요구하는 PGlite 타입을 최소 SQL query/transaction 인터페이스로 분리하고 PGlite 테스트 어댑터와 서버 PostgreSQL 어댑터를 둔다. 실제 PostgreSQL 트랜잭션은 하나의 체크아웃된 연결에서 BEGIN/COMMIT/ROLLBACK을 수행하고 실패 시 반드시 반환한다. UUID·JSONB·시간·row 결과 타입의 호환성을 검증한다.

브라우저 합성 seed를 운영 서버에 복사하지 않는다. 버전·체크섬이 있는 명시적 마이그레이션으로 새 전용 DB를 초기화하며 API 시작 시 DDL을 자동 실행하지 않는다. 배포 역할과 마이그레이션 역할을 구분한다. 다중 연결에서 권한 취소 경쟁, 수정 충돌, 중복 요청, 감사 실패 롤백을 실제 PostgreSQL로 검증해야 하며 PGlite 통과만으로 운영 준비를 판정하지 않는다.

## 별도 검증 단위

F02 목표는 유지하면서 다음 의존 순서로 구체적인 구현 계획과 게이트를 나눈다.

1. 운영 기반: Firebase 인증, 교사 등록, PostgreSQL 어댑터·마이그레이션, Vercel 서버, F01 영구 저장과 브라우저 복원.
2. 생성: OpenAI 서버 어댑터, 저장본 스냅샷, 영구 생성 작업·사용량·제한·실패 복구, 초안 검토 UI.
3. 배포: 실제 프로젝트 연결, 합성 예제 운영 검증, 독립 최종 심사, CI 및 기존 Vercel delivery.

전체 목표의 완료는 세 단위가 모두 끝난 뒤에만 선언한다. 전용 자원 생성이 사용자에 의해 확인된 이후에는 외부 자격증명이 필요 없는 로컬 선행 작업을 별도 구체적 계획·86점 게이트로 진행할 수 있다. 이는 운영 연결·마이그레이션·배포의 게이트 통과로 취급하지 않는다. 첫 선행 계획은 `docs/superpowers/plans/2026-09-08-f02-async-auth-boundary.md`이다.

## 공통 설계

### 교사 흐름

저장된 수업 수정본 선택 → AI 초안 생성 → 생성 중 상태 → 생성 결과와 검증 지적 표시 → 교사 미리보기.

생성 요청은 저장된 입력 ID와 예상 revision을 참조한다. 미저장 편집은 먼저 저장하도록 안내한다. 생성 시작 시 제목·학년·본문·목표와 revision을 스냅샷으로 고정한다. 이후 원문 편집은 진행 중인 요청 내용을 바꾸지 않는다.

실패 시 원문과 편집 내용을 유지한다. 재시도는 기존 요청 조회와 새로운 생성 시도를 구분한다. 응답 유실 시 동일 요청을 조회하여 중복 생성과 중복 비용을 피한다. 외부 제공자의 불확실한 완료를 무조건 자동 재호출하지 않는다.

### 서버 권한과 생성

2026-09-09 사용자 추가 확정: 외부 AI 생성은 결제한 교사 계정에만 제공한다. 현재 결제 서비스가 없으므로 **AI 기본 차단**을 선택했다. OpenAI 키 등록, Google 로그인, 교사 승인, 관리자 역할만으로 AI 호출을 허용하지 않는다. 요청마다 서버가 현재 기관·교사 권한과 결제 이용권·사용량을 확인해야 하며 클라이언트의 paid 플래그나 결제 성공 화면을 근거로 사용하지 않는다. 검증된 결제 연동이 마련되기 전에는 운영 생성 경로가 항상 차단되어야 하고 임시 무료/관리자 우회 경로를 만들지 않는다. 결제창/가격/PG 계약은 이번 요청에서 미정이며 임의 결제나 유료 자원 생성은 하지 않는다. 로그인·저장 구현은 계속 진행한다. 향후 실제 OpenAI smoke test도 이 정책과 별도의 적법한 결제 검증 조건을 충족하기 전에는 실행하지 않는다.

생성 서비스는 서버에서만 실행한다. Firebase 검증 uid와 현재 DB 권한으로 요청 주체를 서버에서 결정한다. 클라이언트가 보낸 교사·기관 ID나 미리보기 토큰은 권한 근거로 사용하지 않는다.

서버의 현재 권한 확인 후 입력을 읽고 스냅샷과 요청 식별자를 보존한다. 제공자 호출을 긴 DB 트랜잭션 안에서 수행하지 않는다. 결과 저장 전 권한을 다시 확인한다. 기관·요청 주체별 조회 격리와 일반화된 접근 실패 응답을 적용한다.

모델에는 수업 생성에 필요한 텍스트만 전달한다. 인증정보·학생·반 데이터는 포함하지 않는다. 입력은 지시가 아닌 자료로 취급하고 도구 실행·외부 URL 접근·임의 코드 생성을 허용하지 않는다.

제공자·모델은 서버 설정으로 고정한다. 요청 크기, 출력 크기, 토큰, 시간 제한, 동시 실행 수, 호출량 제한과 비활성화 설정을 둔다. 실제 저장·배포 형태에 맞는 제한 저장소를 선택하며 서버리스 프로세스 메모리만으로 전역 제한을 보장한다고 주장하지 않는다.

### 출력과 검증

기존 science BlockSpec을 재사용하는 경우 설명 → 예측 → 힘과 운동 실험 → 문항 → 성찰 순서를 보존한다. 생성 힌트는 현재 스키마에 없는 항목이므로 별도 엄격한 초안 계약에 두고 교사 검토에 표시한다. 학생 Rasa 연결까지 암묵적으로 확장하지 않는다.

외부 출력은 신뢰하지 않는다. JSON 구문, 필수 항목, 길이, ID 참조, 정답 단일성, 학습목표 연계와 기존 과학 검증을 적용한다. 구조 오류는 안전한 필드 경로와 교사용 안내로 표시하고 원시 제공자 오류·응답·비밀은 진단 로그에 남기지 않는다. 구조 검증만으로 사실 정확성 검증을 완료했다고 표시하지 않는다.

성공한 초안도 자동 승인·게시하지 않는다. 기존 불변 버전·독립 검증·교사 승인 경계를 유지한다. 모델 생성과 별도의 콘텐츠 검증 방법은 구현 계획에서 명시한다.

## 예상 영향 파일과 테스트

- `packages/contracts`: 생성 요청·상태·결과·안전한 검증 지적 계약.
- `packages/science-studio`: 제공자 독립 생성 계약, 출력 파싱과 검증.
- 서버 전용 제공자 모듈: 실제 API 호출, 제한과 오류 변환. 브라우저 배럴에서 분리.
- `packages/db` 및 `services/api`: 확정된 운영 경계에 맞는 요청 저장·권한·조회·재시도.
- `apps/web`: F01 저장본 생성 버튼, 진행·실패·재시도, 결과·힌트 검토와 기존 미리보기 연결.
- 서버 진입점과 배포 설정: 운영 경계 확정 뒤 파일별 계획으로 구체화.

RED/GREEN은 엄격한 계약 → 제공자 오류·시간 초과·출력 검증 → 권한·스냅샷·중복·재시도 저장 → 실제 HTTP 경계 → React 원문 보존·상태 전환 → 브라우저 순서로 수행한다. 정상 생성뿐 아니라 다른 기관·사용자 조회, 권한 취소, 손실 응답, 중복 요청, 오래된 화면 응답, 과대 입력·출력, 악성 자료, 키와 응답의 번들·로그 누출을 검증한다.

기존 전체 check, integration, E2E, demo/preview browser, production audit와 배포 검증을 유지한다. 실제 제공자 검증은 비밀 설정과 호출 범위 확정 후 비민감 예제 자료로 수행하며 대체 테스트와 구분해 기록한다.

## 게이트와 복구

전용 운영 대상·연결 확인 → 파일별 구현 계획 및 100점 사전 심사 → 86점 이상·차단 없음 → TDD 구현 → 독립 최종 심사 86점 이상 → CI·main 통합·기존 Vercel 배포 검증 순서다.

현재 문서는 검토 가능한 설계 초안이며 구현 게이트 통과나 완료 증거가 아니다. 영구 데이터베이스 연결은 요청 범위에 포함하며 유료 자원 구매·실제 학생 데이터·참조 저장소 변경은 포함하지 않는다. 사용자 요청은 LessonQuest 전용 신규 Firebase 인증 연결을 허용하지만 기존 Phase 1 금지를 근거 없이 전체 Firebase 데이터 접근 허용으로 확대하지 않는다. 생성 비활성화 시 기존 승인 콘텐츠 플레이가 계속 가능해야 하며, 코드 복구는 검토된 커밋 revert를 사용한다. 마이그레이션 전 대상 식별, 백업·복구 가능성 및 독립 staging 검증이 필요하다.

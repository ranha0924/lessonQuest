# Phase 2 첫 전달 단위: 반·초대·교사 대시보드

## 범위와 선택

`PROJECT_CANON.md`와 `INTEGRATION_PLAN_V2.md` §14의 작은 단위 이식을 따른다. Phase 1은 합성 데이터 범위에서 완료됐고 quiz/boss 서버 판정은 이미 연결되어 있다. 이번 단위는 교사가 반을 만들고 선택하고, 학생이 초대 코드로 가입하며, 교사가 반 전체 과제 진행을 다시 읽는 흐름이다. 사용자의 “Phase 2 진행해”와 상시 전달 권한에 따라 진행한다. 새 과목, PWA/offline 저장, 외부 인증 매핑/실데이터 전환은 별도 후속 단위다. Phase 2 전체 완료로 표시하지 않는다.

기존 tenant 저장소에 모든 기능을 넣거나 원본 앱을 복사하는 대신, 별도의 ClassroomRepository와 작은 UI를 추가한다. 기존 authoring/player/event 경계와 다크 디자인을 재사용한다. 외부 WordQuest 소스를 이번 단위에서는 읽거나 복사하지 않으며 기능 요구에서 새로 작성한다.

## 기능과 권한

- 교사 반 목록: 활성 기관 membership와 현재 DB platform role을 확인하고, 소유 반 또는 ORG_ADMIN 범위만 반환한다. 다른 교사 반을 조회/관리할 수 없다.
- 반 만들기는 기존 엄격한 API를 재사용한다. 새 반을 선택하면 Studio를 새 key로 마운트하여 과거 반의 과제/보스/초안 상태를 사용하지 않는다. 기존 기본 반의 Studio는 기존 역할 전환 복구를 보존한다.
- 교사 대시보드: 활성 학생 수와 활성·게시된 과제별 시작/완료/오답/재도전/힌트 합계를 서버 projection에서 계산한다. 학생 식별자/명단/순위는 반환하지 않는다. 미래/기한 종료 과제도 교사용 현황에는 포함한다. 비활성 학생/소속은 현재 집계에서 제외한다. 과제별 기존 상세 보기로 이어진다.
- 초대 생성: 반당 활성 초대 한 개, 서버 무작위 UUID 두 개로 만든 244비트 코드, SHA-256만 저장, 24시간 만료, 교사가 정한 1–100명 한도. 재발급은 이전 코드를 원자적으로 취소한다. 응답 유실 시 다시 발급하여 안전하게 회복한다; 과거 원문 코드는 복원하지 않는다.
- 초대 취소: 권한을 다시 확인하고 지정한 초대만 취소한다. 반복 취소는 동일한 안전한 응답을 낸다. 오래된 ID의 취소는 새 초대를 취소하지 않는다.
- 학생 가입: 인증된 현재 활성 STUDENT만 코드로 자기 자신을 등록한다. actor/role/userId를 body에서 받지 않는다. 코드는 POST body에만 보낸다. 기관·반·초대·발급자 권한·학생 및 기존 소속 상태를 트랜잭션에서 검증한다. 발급자가 권한을 잃으면 초대도 무효다. 비활성 소속을 되살리지 않는다.
- 같은 학생의 정상 재전송은 DUPLICATE이며 인원 한도를 더 소비하지 않는다. 기존 활성 반 소속도 DUPLICATE다. 만료/취소/권한철회 후 재전송은 거절한다. 한도는 초대 row lock과 조건부 UPDATE, 소속 unique 키로 보호한다. 코드 오입력/타기관/만료는 같은 404로 처리한다.
- 모든 조회·발급·취소·가입은 allowlist 감사 로그를 남긴다. 거절/충돌 감사는 rollback 후에도 남고 감사 저장 실패는 500으로 닫힌다. 코드, 코드 hash, 요청 body, 이름/답안은 감사/진단에 남기지 않는다. API는 no-store를 적용한다.

## 전달 환경과 제한

배포는 기존 합성 개발 미리보기다. 기존 로그인·DB·Firebase와 연결하지 않는다. 모든 DB는 탭 메모리이며 새로고침하면 코드·가입·학습도 초기화된다. 공개 코드 배포/메일 전송은 수행하지 않는다. 초대 코드는 사용자에게 화면에서만 제공한다. 운영 도입 전 외부 인증, 요청 제한, 실제 PostgreSQL 동시성 검증, 지속 DB의 migration 및 운영 정책이 필요하다. 이번 추가 테이블은 fresh/local schema에만 적용한다.

## 1. Firebase Authentication

1. https://console.firebase.google.com/ 에서 LessonQuest 전용 프로젝트를 만든다. 다른 서비스의 프로젝트는 재사용하지 않는다. 표시 이름은 LessonQuest로 할 수 있으며 실제 project ID는 생성 결과를 사용한다.
2. 프로젝트 안에 웹 앱을 등록한다. Firebase Hosting은 필요하지 않다.
3. Authentication → Sign-in method에서 Google 제공자를 활성화하고 지원 이메일을 지정한다.
4. Authentication 설정에 실제 LessonQuest 배포 도메인을 승인된 도메인으로 등록한다. 무작위 preview 도메인 전체를 허용하지 않는다. 개발 도메인은 개발 설정에서만 추가한다.
5. 우선 프로젝트 ID만 공유한다. 웹 앱 설정과 서버 인증정보는 실제 연결 단계에서 구분하여 설정한다.

Firebase 웹 앱 설정(apiKey, authDomain, projectId, appId)은 클라이언트 설정이며 서버 관리자 자격증명과 다르다. 서비스 계정 비공개 키·JSON 파일은 채팅이나 저장소에 넣지 않는다. 서버에서 필요한 자격증명은 전용 비밀 설정으로 제공한다. 가능한 배포 신원 연동 방식과 서버 SDK 요구 권한을 확인한 후 선택한다.

## 2. Neon PostgreSQL

1. 기존 LessonQuest Vercel 프로젝트의 Storage/Marketplace에서 Neon을 연결한다. 또는 전용 Neon 프로젝트를 만든 뒤 기존 Vercel 프로젝트에 연결한다.
2. 초기에는 사용 가능한 무료 요금제 안에서 준비한다. 유료 결제나 자동 업그레이드가 필요한 화면에서는 진행하지 않고 비용과 이유를 확인한다.
3. 개발/preview와 production DB를 분리한다. preview 배포에 production 쓰기 연결을 제공하지 않는다.
4. DB 지역과 Vercel 함수 지역을 맞출 수 있도록 실제 제공 지역을 연결 단계에서 확인한다.
5. 연결 문자열은 서버 비밀 환경변수로만 설정한다. 채팅에 보낼 정보는 프로젝트 이름·연결 완료 여부이며 비밀번호가 아니다.

마이그레이션은 코드와 독립 검증 게이트 통과 후 전용 새 DB에서 실행한다. 기존 또는 식별 불명 DB에는 스키마 초기화를 실행하지 않는다. 운영 연결은 TLS를 사용하고 인증서 검증을 끄지 않는다.

## 3. OpenAI

- 기존 키를 사용할 수 있으나 프로젝트별 사용량을 구분할 수 있는 LessonQuest 전용 키가 적합하다.
- `OPENAI_API_KEY`는 Vercel 서버 환경변수로 설정한다. `VITE_` 접두사를 붙이지 않는다.
- 모델 후보는 `gpt-5.6-luna`. 계정 접근 가능 여부를 실제 호출 전에 확인한다.
- 초기 생성 횟수·토큰·동시 실행·일별 한도를 앱 서버에서 제한한다. 대시보드 예산 알림만을 하드 차단으로 취급하지 않는다.
- 실제 호출 확인에는 비민감 수업 예제만 사용한다.

## 4. 교사 권한과 운영자

Google 로그인과 교사 승인은 별개다. 첫 운영자의 Firebase uid를 명시적 부트스트랩 설정으로 지정한다. 첫 방문자 자동 관리자 승격은 금지한다. 교사는 서버 승인 기록에 따라 기관에 연결한다. 이메일 도메인이나 클라이언트 역할 필드만으로 기존 기관에 접근시키지 않는다.

## 5. Cloudflare

초기 연결에는 필요하지 않다. 기존 Vercel 서버와 PostgreSQL 구성을 먼저 사용한다. 추후 별도 도메인 DNS나 봇 방어 등이 필요할 때 해당 기능만 검토한다. 이번 설정 때문에 호스팅을 이전하거나 D1로 DB를 다시 작성하지 않는다.
